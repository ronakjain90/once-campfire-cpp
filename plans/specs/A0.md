# A0: App framework

Owns: `src/app/` (except `main.cpp` boot code that exists: extend it), `src/models/` (only the files this task needs: session, user, account basics), `src/views/sessions/`, `tools/diffsweep/lists/` (only volatile-header settings, see below).
Uses: every merged library: `src/core`, `src/net` (T5), `src/req` (T6), `src/db` (T7), `src/views`, `src/routes` (T8), `src/assets` (T9), `src/compat` (T2), `src/richtext` (T3, T10).
Spec: `plans/architecture.md` sections 3 to 7. This task connects the libraries. Later area tasks (A1 to A9) add features on top of it, so make the APIs clear and document them in `src/app/README.md`.

## Scope

1. **App state.** One immutable `App` object built at boot: config, `Secrets`, the database (`Database`, the writer), the asset table, the shared caches. Per-worker state: the read connection, the session cache, the worker's `Scheduler`. `Ctx` gives handlers access to both.
2. **Session cache** (architecture 6): per worker, from the raw `session_token` cookie value to the session row and the user row. A database change subscriber clears entries on changes to `sessions` and `users` on every worker (post to each worker; do not share mutable state).
3. **Concerns**, as Rails and the Rust port do them (`reference/app/controllers/concerns/*`, `once-campfire-rust/crates/campfire/src/concerns*`): authentication (`require_authentication`, resume session, the hourly `last_active_at` refresh and the re-signed cookie, `return_to_after_authenticating`), set current request, block banned requests (IP bans), version headers, the forgery protection call (T6), and a hook for `allow_browser` and platform detection (A1 implements the user-agent rules; provide a default that passes).
4. **Responses**: render a page in the layout (T8 `LayoutParts`, `ViewContext` filled from the asset table, current user and account), Turbo Stream responses, `redirect_to` with flash (`notice`, `alert`), `head`, JSON, `send_file` hook, gzip with libdeflate for dynamic bodies, ETag and conditional GET as Rack::ETag and Rack::ConditionalGet do, the exact header order of the Rust responses.
5. **Caches**: the real fragment cache (shared, sharded, bounded by bytes, `CAMPFIRE_FRAGMENT_CACHE_MB`, default 32) installed for each worker through `views::set_fragment_cache`; the page cache of architecture 6.1 (key from the T7 dependency scope plus facets; identity, gzip and ETag per entry; bounded by bytes), and the audit (in asan and tsan builds, re-render on 1 hit in 16 and compare bytes; a difference is a fatal error in tests). For pages where the Rust ETag hashes page parts (room, messages, search: Rust README "Caching"), the ETag value cannot match Rust: keep the format `W/"<32 hex>"` and add `etag` to the volatile headers of those routes in the diff sweep lists.
6. **Errors**: 404, 422, 500 and the other error responses with the exact bytes of the Rust port (`crates/kit/src/exceptions.rs`, `public/*.html`); an exception in a handler gives the 500 response and a log line.
7. **Proof routes**: the sign-in flow, end to end: `GET /session/new`, `POST /session` (bcrypt through `ctx.offload`, the session row through the writer, the signed `session_token` cookie, the sign-in rate limit as Rails/Rust do it), `DELETE /session`, and the redirect of an unauthenticated request to the sign-in page. Templates in `src/views/sessions/` (`.ct`, line for line from the ERB files).
