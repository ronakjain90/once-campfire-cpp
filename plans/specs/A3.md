# A3: Messages (write side), boosts, the bot API, broadcasts

Owns: the controllers, models, jobs and route files of this area in `src/app/`, `src/models/`, `src/views/` (one file per controller or template; do not edit files of other areas), `tools/diffsweep/lists/*A3*` (only to add missing requests).
Uses: everything on `main`: the A0 framework, A1, `src/db` (writer, after-commit, change events), `src/richtext` (sanitize, attachments, mentions, plain text), `src/storage` (attachments), `src/cable` (the hub: broadcasts only; the channels are A7).
Behavior: Rails `reference/app/controllers/messages_controller.rb` (create, edit, update, destroy; NOT index), `messages/boosts_controller.rb`, `messages/by_bots_controller.rb`, `messages/boosts/by_bots_controller.rb`, `autocompletable/users_controller.rb`, the Message, Boost, Membership and Room models and their callbacks (in Rails order), `app/jobs/room/*`, `app/jobs/bot/*` (enqueue only; delivery is A9). Exact bytes: the Rust port (`once-campfire-rust/crates/campfire/src/controllers/messages*`, `channels`, `jobs`).

## The split with A2 (rooms, in another session)

A2 owns the message display partials (`messages/_message` and the partials it uses) and `GET /rooms/:id/messages`. A3 must not write those templates. Call the message partial through one declared function, `campfire::views::messages::message(Out&, const MessageView&, ...)`: declare it in `src/app/message_partial.hpp` with the inputs the Rails partial needs, and give a temporary implementation in `src/app/message_partial_stub.cpp` that is clearly marked as a stub. When A2 merges, Opus replaces the stub with A2's partial.

## Scope

- Message create (form and multipart upload with attachments, `client_message_id`), edit, update, destroy; the Turbo Stream responses; the rules on who can edit or delete.
- Boosts: create and destroy, the boost touch on the message.
- The bot API (`/rooms/:room_id/:bot_key/messages`, create, update, destroy, boosts) with the bot key check and the forgery exemption.
- User autocomplete (`/autocompletable/users`).
- Model callbacks in Rails order: touch the room, update unread memberships, FTS index after commit, mentions, push job and bot webhook job ENQUEUE (A9 does delivery).
- Broadcasts through the hub after commit (`broadcast_append_to`, `broadcast_replace_to`, `broadcast_remove_to`, unread room broadcasts), with the exact frame bytes of the Rust port.
- **Performance:** the post route is a benchmark route. Use the writer's group commit; run each statement that Rust runs after the commit, or fewer if the result is the same (G3 capture: `gate/capture/summary.md`); keep rendering off the writer thread.
