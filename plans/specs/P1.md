# Performance pass: the sidebar and posts at 64 clients

Owns: the sidebar code (`src/app/controllers/` sidebar files, its models and templates), the post path (`src/app/message_actions.cpp`, the messages controller), `src/db/` (writer tuning only). Do not change behavior: the diff sweep must stay at 0 in every area.
Spec: `plans/architecture.md` sections 5 and 6; `plans/cpp-port.md` goal 2 (at least 1.5 times the Rust port on each benchmark route).

## Measured gap (2 reps, `gate/bench/run`, on this host)

| Route | 1 client | 16 clients | 64 clients |
|---|---:|---:|---:|
| sidebar (C++ / Rust) | 0.92x | 0.63x | 0.75x |
| post_message (C++ / Rust) | 1.4x | 1.5x | 0.92x |

## Scope

1. Profile both routes with `perf` in the container (the VM kernel is 6.8; install `linux-tools` in a profiling container or on the VM) and find where the time goes.
2. Sidebar: it must use the page cache with all inputs in the key (see how the room page does it in `src/app/controllers/room_pages.cpp`), and run no statement more than Rust does (`gate/capture/summary.md` and the Rust trace image `campfire-rust:trace`).
3. Posts at 64 clients: check the group commit (batch size, wake-ups), the after-commit reads, rendering on the worker, and lock or queue contention.
4. Record each change with before and after numbers in `bench/results/<date>-<topic>/`.

## Acceptance (raw output in the report)

- `bin/dev build` and `bin/dev test` for release, asan, tsan pass.
- Diff sweep: every area stays at 0 differences.
- `gate/bench/run --apps rust=campfire-rust:app,cpp=campfire-cpp:<tag> --routes sidebar,post_message,room_show --reps 3`: sidebar and post_message at least 1.5x Rust at 16 and 64 clients, room_show not slower than now.
