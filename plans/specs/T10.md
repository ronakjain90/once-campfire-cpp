# T10: Rich text attachments

Owns: `src/richtext/` (additions only: attachments, autolink, plain text, presentation). T3's code is merged there: extend it, do not rewrite it.
Uses: `src/core`, `src/compat` (SGID, the User-only SGID fallback, signed ids, ERB escape), `src/richtext`.
Spec: `plans/architecture.md` section 9. Behavior spec: `once-campfire-rust/crates/richtext`, `crates/campfire/src/rich_text.rs`, the Rust README "Rich text attachments" and "Malformed rich text". Ground truth: Rails Action Text in `campfire-reference:app` and `reference/lib/rails_ext/action_text_attachables.rb`.

## Scope

- Action Text attachments in message bodies: mentions by SGID (with the User-only fallback for invalid signatures), opengraph embeds, nesting limit of 8, deleted-user mentions (render ☒ and omit in the editor), Active Storage attachments in bodies (render ☒), as the Rust README says.
- Autolink, with `<` and `>` escaped in attributes (Rust "Known differences").
- Plain text extraction, as Action Text `to_plain_text`, with the Rust failure rules.
- The outputs that the corpus records for each case: `presentation` (the HTML of a message body on a page, including the attachment partials), `presentation_raised`, `plain_text`, `editable` (the HTML for the editor), `mentioned` (the user ids), `filtered`. The attachment partials are small: render them in C++ inside `src/richtext/` with a plain struct for the user data they need (name, avatar URL, etc.). Do not wait for the template work of other tasks.
- The data the corpus needs (users, rooms, signed values, request host) is in the top part of `once-campfire-rust/crates/richtext/tests/corpus/expected.json`. Provide a small lookup interface (user by id, and so on) that the tests fill from that file and the app fills from the database later.

## Acceptance (raw output in the report)

- `bin/dev build` and `bin/dev test` for release, asan, tsan pass.
- All 658 corpus cases: for each output field (`presentation`, `presentation_raised`, `plain_text`, `editable`, `mentioned`, `filtered`), the number equal to the expected value. Every case must pass, or list each failure with its exact reason.
- Extend the fuzz target to the full pipeline (sanitize, attachments, autolink, plain text). Run it 5 minutes in the background. No crash.
