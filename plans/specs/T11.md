# T11: Cable core

Owns: `src/cable/`.
Uses: `src/core`, `src/compat` (JSON, Turbo signed stream names). Do not depend on `src/net` (T5).
Spec: `plans/architecture.md` section 10. Behavior spec: `once-campfire-rust/crates/cable` and the reference frames it was checked against (in that crate's tests and test data).

## Scope

A transport-agnostic library:
- A WebSocket codec: handshake check and accept header from request headers, frame parse and serialize, masking, fragmentation, control frames, close codes, `permessage-deflate` negotiation and no-context-takeover compression.
- The Action Cable protocol state machine: welcome, ping, subscribe, confirm, reject, unsubscribe, message and perform, disconnect with the reconnect flag. The limits of the Rust README ("Cable limits"). The exact JSON bytes of every server frame (key order, spaces) and the ping interval.
- The Hub: stream to set of workers. A broadcast encodes a frame once, plain and deflated, reference-counted, and posts it to per-worker delivery queues.
- Interfaces for the transport (bytes in and out, close), the channel handlers (subscribe and perform callbacks, written later in `src/app/channels/`) and the worker post function (T5 provides it).

## Acceptance (raw output in the report)

- `bin/dev build` and `bin/dev test` for release, asan, tsan pass.
- Tests driven by the Rust crate's reference frames (case and pass counts), WebSocket codec tests with RFC 6455 edge cases, `permessage-deflate` interop in both directions with zlib, hub tests with many workers under tsan.
- A libFuzzer target for the frame parser, run 3 minutes in the background, no crash.
- A micro-benchmark: deliveries/s of a 10 KB broadcast to 10,000 in-memory subscribers across 4 worker queues.
