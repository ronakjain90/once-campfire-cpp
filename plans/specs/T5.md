# T5: Server

Owns: `src/net/`, `src/app/main.cpp`, the route table format (`src/app/routes/`), `tools/routes_gen.py`, `vendor/picohttpparser/`, the real build step in `docker/Dockerfile`.
Uses: `src/core` (Task, Completion, Scheduler, Out, Arena, Config, Clock, log). Read their headers.
Do not edit: `src/req/` (T6), `src/db/` (T7), `src/views/`, `src/routes/` (T8), `src/assets/` (T9), `src/cable/` (T11), `src/storage/` (T12), `tools/diffsweep/` (T13).

## Scope

1. Worker threads: one per CPU in the cpuset (`sched_getaffinity`). Each has an `epoll` loop, its own `SO_REUSEPORT` listeners for `HTTP_PORT` and `TARGET_PORT` (bind per `TARGET_BIND`, default loopback, as the Rust config), a hashed timer wheel, and an MPSC queue with an `eventfd` for posts from other threads. The worker implements the core `Scheduler` interface, so `Completion` and `Task` resume on the owner worker.
2. HTTP/1.1 with vendored picohttpparser: keep-alive, pipelining, bodies by Content-Length and chunked, limits and timeouts as the Rust port (`HTTP_IDLE_TIMEOUT`, `HTTP_READ_TIMEOUT`, `HTTP_WRITE_TIMEOUT`, `MAX_REQUEST_BODY`, the 16 MiB rules; read `once-campfire-rust/crates/kit/src/front` and the Rust README "Front server"), 100-continue, HEAD, connection close rules. A libFuzzer target for the request parser.
3. Response builder: status line and headers in insertion order (exact order matters), body as an arena buffer or a slice of a reference-counted immutable entry, chunked framing (Rust sends gzip responses chunked: see `gate/capture/raw/*response-headers.txt`), one `writev`, partial writes with `EPOLLOUT`.
4. Router: a build-time table from per-area files `src/app/routes/<area>.inc` (design the format, e.g. `GET /rooms/:room_id/messages messages::index`). Match method and segments with no regex and no heap allocation. Path params into `Ctx`. Rails formats (`.json` suffix) and the `@:message_id` route. Generated by `tools/routes_gen.py` at build time.
5. `Ctx`: request view, per-request Arena, path params, response builder, worker access, extension slots for the database handle (T7) and the session (T6) with no logic of theirs, and `co_await ctx.offload(pool, fn)` with a simple blocking thread pool.
6. `src/app/main.cpp`: boot config, start workers, serve `GET /up` exactly as the Rust app (capture headers and body from `campfire-rust:app` with and without `Accept-Encoding: gzip`), and 404 for unknown routes in the Rust format.
7. `docker/Dockerfile`: put the real build (`cmake --preset release`, binary under `/build/release/`) in the cpp-build stage in place of the placeholder, so `docker build -t campfire-cpp:app -f docker/Dockerfile .` gives an image whose `/up` works in the G2 harness.
