# T6: Request parts

Owns: `src/req/` (library `campfire_req`), `vendor/crypt_blowfish/`.
Uses: `src/core`, `src/compat` (cookies, MessageEncryptor, Secrets, Ruby helpers, JSON).
Do not depend on `src/net` (T5). Write pure functions and classes over `std::string_view` inputs (header values, query strings, bodies) and a core `Arena`, so T5 and the controllers can call them.

## Scope

Match the Rust port exactly. Read `once-campfire-rust/crates/kit/src/{params.rs,cookies.rs,session.rs,request.rs,format.rs,ctx.rs}`, and the Rails and Rack sources in `campfire-reference:app` for edge cases.

- Rack-compatible query and form params with nested keys (`a[b][]=`), the same limits and errors as Rack and Rails, and `permit` and `require` helpers equal to Rails strong params as Campfire uses them.
- `multipart/form-data`: streaming, bounded memory, files spill to a temp file in the storage tmp directory as the Rust port does, with the Rust request limits (README "Request limits").
- Cookies: parse the Cookie header as Rack does. Format Set-Cookie with the attribute order of the Rust responses (see `gate/capture/raw/*response-headers.txt`; capture more from `campfire-rust:app` if needed). Signed `session_token`. Encrypted `_campfire_session` (AES-GCM, 20-year expiry) through compat. Session written only on change, deleted when empty (Rust "Known differences"). Flash in the session, as Rails.
- Forgery protection: the `Sec-Fetch-Site` rules of the Rust README ("CSRF"), the Origin check, a hook for the bot-key exemption, and the old masked-token path if the Rust port still accepts tokens. The `csrf` group of `spec/vectors/rails_compat.json` must pass.
- Formats and `Accept` negotiation as Rails (including the infinite q-value rule of the Rust README), and `.json` route formats.
- bcrypt with vendored `crypt_blowfish` (Openwall, public domain) and a CMake target: verify and create as `has_secure_password` does, with the Rails cost. The `passwords` group of `spec/vectors/rails_compat.json` must pass. Callers offload bcrypt.
- libFuzzer targets for query params, multipart, the Cookie header and the Accept header (`src/req/fuzz/`, built only with `-fsanitize=fuzzer`).
