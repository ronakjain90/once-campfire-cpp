# T7: Database

Owns: `src/db/`, `tools/schema_gen.py`, `vendor/sqlite/`, `spec/schema.rb`.
Uses: `src/core` (Task, Completion, Scheduler, Arena, Clock, Xxh3, log). Depend only on the core Scheduler and Completion interfaces. Test with `QueueScheduler` and plain threads (T5 builds the real worker loop).
Spec: `plans/architecture.md` sections 5 and 6.1. Prototype to learn from (do not copy its shortcuts): `gate/server/src/writer.cpp`, `db.cpp`.

## Scope

1. Vendor the SQLite amalgamation at the version the Rust port bundles (rusqlite 0.40 bundled, 3.53.x: check `once-campfire-rust/Cargo.lock` and the libsqlite3-sys sources) with the same compile options (FTS5 and others), with a CMake target.
2. Connections with the pragmas of the Rust port (`crates/db/src/schema.rs`, `database.rs`). Readers are `query_only`.
3. `tools/schema_gen.py` reads `spec/schema.rb` (a copy of `reference/db/schema.rb`) and writes `src/db/schema.gen.hpp`: a struct for each table, column lists, row readers into the Arena. The build regenerates it when `spec/schema.rb` changes.
4. Typed statements: `constexpr Query<Row(Args...)>` with a static index; a lazily prepared array on each connection; binding of int64, double, text, blob, null and optional; step into rows; `first`, `all`, `exec` helpers; errors as `std::expected`.
5. Dependency tracking (architecture 6.1): a request scope that folds the statement index, the parameter values and the raw bytes of each returned row into an XXH3-128 state, plus facets, plus an "uncacheable" flag. Keep the overhead small and measure it.
6. Writer thread with group commit: up to 64 queued writes in one transaction, each in its own SAVEPOINT (roll back only the failing one). `co_await db.write([&](Tx& tx){...})` in a Task returns the lambda's result on the submitting worker. `tx.after_commit(fn)` runs on the submitting worker after COMMIT. `tx.changed(table, id)` events are published after the commit to registered subscribers. Writes never block a worker thread.
7. Checkpointer thread: `wal_autocheckpoint=0` on the writer, PASSIVE when the WAL passes 1,000 pages, RESTART rules as the Rust port (`crates/db/src/database.rs`).
8. Timestamps written exactly as Rails and Rust write them (microseconds, format), with the core time formats.

## Acceptance (raw output in the report)

- `bin/dev build` and `bin/dev test` for release, asan, tsan pass.
- Tests: group commit with a failing write in the middle (the others commit), after-commit order for each write, change events, the statement cache, a dependency hash that is stable and changes on any row change, the writer with 64 concurrent submitters (tsan clean), checkpoints with a growing WAL.
- A micro-benchmark: reads/s of a 40-row query on one connection, the dependency tracking overhead in %, writes/s with group commit and with one transaction for each write, on a VM-local file (`/var/lib/campfire-bench/t7/`).
