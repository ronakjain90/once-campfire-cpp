# T9: Assets

Owns: `src/assets/`, `third_party/`.
Behavior spec: `once-campfire-rust/crates/assets` and its `OVERRIDES.md`. Ground truth: the Propshaft output of the reference app in `campfire-reference:app` (`public/assets`).

## Scope

1. Copy into `third_party/rails-assets/` every frontend file the app serves: `reference/app/assets/**`, `reference/app/javascript/**`, the vendored gem assets that the Rust crate ships (Turbo, Stimulus, Lexxy, Action Cable, request.js, highlight.js and others), and the Rust port's overrides (`crates/assets/overrides`). Keep licenses. Write `MANIFEST.md` with the source and SHA-256 of each file.
2. Propshaft-compatible logical paths, digests and digested file names, CSS `url()` rewrite as Propshaft does, and the importmap output exactly as the Rust port renders it (`config/importmap.rb`).
3. Preparation at build time where possible (principle 1), else at boot: an immutable table of assets with identity, gzip and zstd bodies, content types, cache headers and ETags exactly as the Rust port serves them (capture headers from `campfire-rust:app` for a CSS, a JS, an image and a font if any).
4. An API for other tasks: logical path to digested path (for view helpers), and request path to response entry (for the server).

## Acceptance (raw output in the report)

- `bin/dev build` and `bin/dev test` for release, asan, tsan pass.
- For every asset, the digested name equals the Rust port's (and the Rails reference's): counts of total, equal, different, with the reason for each difference.
- Each served body (identity) is byte-equal to `campfire-rust:app`. Header comparison for 4 representative assets.
- The importmap output is byte-equal to the Rust port's page output.
